# R5: Web dashboard A

## Mission

Build an independent, complete web dashboard showing a live risk view and alert
history. This is a fallback surface for the RN app (primary). Only one of the two
dashboards (A or B) will ship.

A second, independent dashboard is being built in parallel by R6. Do not look at R6's
folder or coordinate with R6. Divergence is the point; we are choosing between two
takes, not merging them.

## Folder you own

`web/dashboard-a/`. You may not edit any other folder.

## Read first, in order

1. `AGENTS.md` - scope, what Round 1 means, what the app does
2. `contracts/risk.py` - AppMessage, SessionStart, RiskUpdate, CallEnded, RiskLevel,
   RiskVerdict, DEFAULT_BAND_MAPPING
3. `docs/interfaces.md` section 3.5 - the app contract prose

## Start here

Paste this into your coding agent:

```
I am building Web Dashboard A for SATYACHECK. I own web/dashboard-a/. A second,
independent dashboard is being built in parallel by R6 in web/dashboard-b/. Do not
look at that folder or coordinate with R6.

This dashboard is a fallback surface. The RN app is primary. Only one dashboard will
ship.

Read these files first: AGENTS.md, contracts/risk.py, docs/interfaces.md (section 3.5).

Build a fake local WebSocket server that emits AppMessage JSON matching
contracts/risk.py exactly. Then build a web dashboard that connects to it and
displays:

1. Live risk view: current score (0-100), verdict (genuine/synthetic/unknown),
   risk_level (low/medium/high/critical), confidence (0-1), contributing checks,
   degraded checks, reasons. Update roughly once per second.
2. Alert history: a scrollable list of past RiskUpdate messages or CallEnded events,
   timestamped.

AppMessage is a discriminated union on kind: "session_start" (SessionStart),
"risk_update" (RiskUpdate), "call_ended" (CallEnded).

RiskUpdate fields: kind, stream_id, call_id, sequence, timestamp, score (0-100),
verdict, risk_level, confidence (0-1), reasons (list of ReasonCode strings),
contributing_checks, degraded_checks, evidence_refs, schema_version ("1.0").

DEFAULT_BAND_MAPPING: 0=low, 40=medium, 70=high, 90=critical. The dashboard renders
RiskLevel; it never computes a band from score.

SessionStart: show a scanning/connection indicator.
RiskUpdate: the main live display.
CallEnded: show final score, verdict, and whether an alert was raised.

Consume the same RiskUpdate contract from contracts/risk.py, unmodified, so this
dashboard can swap in for the RN app. Do not edit contracts/.

You are free to choose framework, layout, and visual approach. Beyond the live view
and alert history, no enrolment UI, no settings.

Do not edit contracts/, backend/, ml/, acquisitions/, app/, tests/, or docs/. Show a
plan before writing any code.
```

## Self-check

1. Start the fake WebSocket server. Open the dashboard in a browser. Verify messages
   arrive and the live view updates.
2. Kill the WebSocket server. Verify the dashboard shows a clear disconnected state,
   not a frozen last score.
3. Verify the RiskUpdate JSON your fake server emits matches the Pydantic model:
   `uv run python -c "from contracts.risk import RiskUpdate; RiskUpdate.model_validate_json(open('path/to/your/test/message.json').read()); print('valid')"` (or equivalent).
4. Verify the dashboard renders all four RiskLevel values by feeding one of each.
5. Check that no file outside `web/dashboard-a/` was created or modified.

## If you are blocked

1. Try: re-read `contracts/risk.py`. Every field is defined there.
2. Try: search for "RiskUpdate" in the codebase to see if anyone else has written a
   fake server you can reference.
3. If still blocked, append to `QUESTIONS.md` using the format in `roles/ROLES.md`.
4. While waiting, switch to: improving the alert history UI, or writing documentation
   for your dashboard's setup and run instructions.

## Never

- Do not edit `contracts/`. Consume RiskUpdate as-is.
- Do not look at or coordinate with R6's dashboard in `web/dashboard-b/`.
- Do not add enrolment UI, settings, or features beyond live risk view and alert
  history.

- Do not claim this is the primary surface. The RN app is primary.

# R4: RN/Expo app

## Mission

Build the React Native overlay app that displays the live risk score over the
foreground app during a call. The hard part first: get a blank overlay drawing over
another app on the physical demo phone.

## Folder you own

`app/`. You may not edit any other folder.

## Read first, in order

1. `AGENTS.md` - scope, the app contract section, what Round 1 means
2. `contracts/risk.py` - AppMessage, SessionStart, RiskUpdate, CallEnded, RiskLevel,
   RiskVerdict, DEFAULT_BAND_MAPPING
3. `docs/interfaces.md` section 3.5 - the app contract prose
4. `README.md` Repo state section - environment (Node v22.23.2, npm 11.12.1)

## Start here

Paste this into your coding agent:

```
I am the RN/Expo app lead for SATYACHECK. I own app/.

Read these files first: AGENTS.md, contracts/risk.py, docs/interfaces.md (section
3.5), README.md (Repo state section).

Build against a fake local WebSocket that emits RiskUpdate messages. Do not wait for
the backend. The fake server should emit one SessionStart, then RiskUpdate messages
roughly once per second with varying scores and verdicts, then a CallEnded.

The hard part first: get a blank overlay drawing over another app on the physical
demo phone before building anything else. The emulator is not enough; the overlay
must work on a real device. This is the thing that proves the demo works.

AppMessage is a discriminated union on kind: "session_start" (SessionStart),
"risk_update" (RiskUpdate), "call_ended" (CallEnded).

RiskUpdate fields: kind, stream_id, call_id, sequence, timestamp, score (0-100),
verdict (genuine/synthetic/unknown), risk_level (low/medium/high/critical),
confidence (0-1), reasons (list of ReasonCode strings), contributing_checks,
degraded_checks, evidence_refs, schema_version ("1.0").

DEFAULT_BAND_MAPPING: score 0-39 = low, 40-69 = medium, 70-89 = high, 90-100 =
critical. The app renders RiskLevel visuals; it never computes a band from score.
Deployments override the mapping in backend policy config, not in app code.

SessionStart: shows a subtle scanning indicator.
RiskUpdate: the main display, updating roughly once per second.
CallEnded: shows final score and verdict.

The overlay must:
- Draw over the foreground app (system alert window or overlay permission)
- Never block, mute, or end a call
- Show nothing (blank/cleared) rather than a stale score when the WebSocket
  connection drops
- Show the risk level with clear colour coding (low=green, medium=yellow,
  high=orange, critical=red)

Stack: React Native + Expo. See README.md for the pinned Node version.

Do not edit contracts/, backend/, ml/, acquisitions/, tests/, or docs/. Show a plan
before writing any code.
```

## Self-check

1. Connect the fake WebSocket server and verify it emits messages. Run:
   `node [your fake server file]` and open a second terminal to confirm with wscat
   or a test script.
2. On the physical phone: install the app, start a call (any call), and verify the
   overlay appears over the call screen. If it does not appear, this is the blocking
   issue; fix it before anything else.
3. Verify the overlay clears when the WebSocket disconnects (kill the fake server).
   A stale score is worse than no score.
4. Verify the overlay does not block call controls (mute, end, speaker). Physically
   tap through every call button with the overlay visible.
5. Feed a RiskUpdate with score=95 and verify the overlay shows red/critical. Feed
   one with score=10 and verify green/low. This proves the mapping works.

## If you are blocked

1. Try: check Expo docs for overlay permissions on Android (SYSTEM_ALERT_WINDOW)
   and iOS (Picture-in-Picture or CallKit overlay).
2. Try: search for "expo overlay foreground app" or "react native system alert
   window".
3. If still blocked, append to `QUESTIONS.md` using the format in `roles/ROLES.md`.
4. While waiting, switch to: building the fake WebSocket server, or designing the
   RiskLevel colour mapping and typography.

## Never

- Do not edit files outside your folder.
- Do not block, mute, or end a call from the overlay. The overlay is display-only.
- Do not show a stale score when the connection drops. Show nothing.
- Do not compute a band from the score. Render the RiskLevel as the backend sends
  it.
- Do not add a settings screen or enrolment UI. Round 1 scope is live risk view and
  alert history only.
- Do not wait for the backend to exist. Build against the fake WebSocket.

# R1: ML lead

## Mission

Build the four AI checks that detect synthetic speech and produce structured evidence
signals. Priority order: machine fingerprint first, then augmentation, then speaker
identity, then prosody and stt_llm, then calibration.

## Folder you own

`ml/checks/machine_fingerprint/`, `ml/checks/speaker_identity/`, `ml/checks/prosody/`,
`ml/checks/stt_llm/`, and any augmentation, calibration, or benchmark code under `ml/`.
You may not edit any other folder.

## Read first, in order

1. `AGENTS.md` - scope, the four checks, what Round 1 means
2. `docs/interfaces.md` - the shared contract prose
3. `contracts/checks.py` - CheckName, CheckStatus, ReasonCode, the four Signal types,
   CheckResult, ChecksBatchResult, Check and CheckRunner protocols
4. `contracts/pipeline.py` - CanonicalAudioChunk, CanonicalAudioBatch, constants
   (16000 Hz, 20 ms, 640 bytes)
5. `contracts/context.py` - CallContext, which flows into every check

## Start here

Paste this into your coding agent:

```
I am the ML lead for SATYACHECK. I own ml/checks/ and augmentation, calibration, and
benchmark code under ml/.

Read these files first, in order: AGENTS.md, docs/interfaces.md, contracts/checks.py,
contracts/pipeline.py, contracts/context.py.

My priority order:
1. Machine fingerprint check (XLS-R + AASIST) in ml/checks/machine_fingerprint/
2. Augmentation pipeline: G.711, AMR-NB, Opus codec simulation and noise injection
   at controlled SNR, all under ml/
3. Speaker identity check (ECAPA-TDNN) in ml/checks/speaker_identity/
4. Prosody check (openSMILE) in ml/checks/prosody/
5. STT + LLM check in ml/checks/stt_llm/
6. Calibration and evaluation

Each check implements the Check protocol from contracts/checks.py. It receives a
CanonicalAudioBatch (16 kHz mono s16le, 20 ms frames) and a CallContext, and returns
a CheckResult with a Signal and EvidenceItems. Read the Signal types in
contracts/checks.py to see what each check must return.

The four CheckName values are: machine_fingerprint, speaker_identity, prosody, stt_llm.
Use exactly these strings. Do not invent new check names.

CheckStatus must be one of: ok, degraded, failed, skipped. A model error returns
failed, never a verdict. Not enough audio returns skipped.

Week-one items:
- Settle the GPU situation (what is available, what runs on CPU)
- Start dataset downloads: ASVspoof 2019, ASVspoof 2021, ASVspoof 5, In-the-Wild,
  MLAAD. Expect 150-200 GB total.
- Verify research code runs on the pinned Python version (3.13.15, see README.md
  Repo state)
- Write down the recording format specification for the Indian-accent benchmark

Metrics to report: EER and cost-weighted metrics (per ASVspoof 5 standard), per-SNR
curve, and Indian-accent false-positive rate. Cost-weighted metrics are mandatory,
not optional; missing a fraud and annoying a real customer are not equally bad
mistakes.

Train directly on 8 kHz G.711 and AMR-NB audio. Phone compression destroys exactly
the detail models rely on. Train on noisy audio as well as clean. Watermark both
classes or neither. Train across corpora; score only on unseen data.

For the STT + LLM check: run STT locally, never stream audio to an external API.
The transcript is an in-memory working artifact of this check only; it must never
appear in EvidenceItem, CheckResult, RiskUpdate, or AlertRecord, and is discarded
when the check returns.

Do not edit contracts/. Do not edit backend/, acquisitions/, app/, tests/, or docs/.
Show a plan before writing any code.
```

## Self-check

Run these alone. No one else's opinion needed.

1. `cd ml/checks/machine_fingerprint/` and verify the directory structure makes sense
   (an `__init__.py`, a module file, a test if one exists)
2. `uv run python -c "from contracts.checks import Check, CheckName, CheckResult,
   MachineFingerprintSignal; print('imports ok')"` from the repo root. If this fails,
   the contract has changed; re-read `contracts/checks.py`.
3. Write a test that instantiates each Signal type with valid field values. Run it:
   `uv run pytest tests/ -q`. All tests must pass.
4. For augmentation: write a test that takes a 1-second 16 kHz mono s16le buffer,
   applies G.711 mu-law encode/decode, and verifies the output is still valid s16le
   with the same length. Run it.
5. For the Indian-accent benchmark: write down (in a markdown file under `ml/`) the
   recording format: sample rate, bit depth, channel count, codec, duration per
   sample, and labelling schema. This is a spec, not code; it must exist before
   recordings are collected.

## If you are blocked

1. Try: re-read `contracts/checks.py` line by line. The answer is usually there.
2. Try: search the repo for existing implementations or stubs.
3. If still blocked, append to `QUESTIONS.md` at the repo root using the format in
   `roles/ROLES.md`.
4. While waiting, switch to: dataset downloads or augmentation pipeline work. Both
   unblock the training loop without needing an answer from anyone.

## Never

- Do not edit `contracts/`. R2 owns it.
- Do not edit `backend/`, `acquisitions/`, `app/`, `tests/`, or `docs/`.
- Do not stream audio to an external API from the STT + LLM check.
- Do not report an EER without the cost-weighted companion number.
- Do not claim "detects deepfakes." The system raises a warning; the human decides.
- Do not watermark only one class. Watermarks go on both classes or neither.
- Do not score on training data or data resembling it. Score only unseen data.

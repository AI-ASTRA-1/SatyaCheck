# R3: Exotel research then acquisition

## Mission

Answer the one blocking question within a week: can Exotel stream call audio during
the call, or only hand over a recording afterwards? Then build both adapters.

## Folder you own

`acquisitions/exotel/` and `acquisitions/webrtc/`. You may not edit any other folder.

## Read first, in order

1. `AGENTS.md` - the "Audio acquisition, Exotel primary and WebRTC fallback" section
2. `docs/interfaces.md` - sections 1 (transport invariant) and 2 (stream lifecycle)
3. `contracts/acquisition.py` - AudioChunk, StreamOpen, StreamClose, AudioStreamAdapter,
   AudioStreamConsumer
4. `docs/interfaces.md` section 8 - import rule matrix for acquisitions

## Start here

Paste this into your coding agent:

```
I am the acquisition lead for SATYACHECK. I own acquisitions/exotel/ and
acquisitions/webrtc/.

Read these files first: AGENTS.md (Audio acquisition section),
docs/interfaces.md (sections 1 and 2), contracts/acquisition.py,
docs/interfaces.md section 8 (import rule matrix).

First task (binary question, answer within one week): can Exotel stream call audio
during the call, or only hand over a recording afterwards? Read Exotel's current

downstream depends on this answer.

If recordings only: the primary path degrades to chunked near-real-time analysis. Say
those words, never "real time". The WebRTC fallback is the mitigation, not a second
product.

After answering, build both adapters. Each adapter implements AudioStreamAdapter from
contracts/acquisition.py and emits AudioChunk, StreamOpen, StreamClose to an
AudioStreamConsumer.

AudioChunk fields: stream_id, call_id, transport (exotel or webrtc), codec (opus,
g711_ulaw, g711_alaw, amr_nb, pcm_s16le), sample_rate, channels (1), frame_ms (20),
sequence (monotonic from 0), payload (encoded bytes), capture_timestamp, received_at,
rtp_ts (optional), metadata (dict).

StreamOpen: one per stream, before the first chunk. Carries direction (inbound,
outbound), caller_number, callee_number (PII, internal only), started_at, codec
properties, external_ref.

StreamClose: one per stream, after the last chunk. reason (completed, dropped,
timeout, error). Carries frames_received, bytes_received, dropped_frames.

The transport invariant: nothing below stage 02 may import or branch on which
transport delivered the audio. Your adapters live entirely above stage 02. To enforce
this, write tests/test_transport_invariant.py extensions (ask R2) or verify with:
grep -r "exotel\|webrtc" backend/ ml/ --include="*.py" should return nothing.

Do not edit contracts/, backend/, ml/, app/, tests/, or docs/. Show a plan before
writing any code.
```

## Self-check

1. Verify the Exotel streaming question is answered with a cite to their official
   documentation (not a blog post, not Stack Overflow).
2. Write a test that imports AudioStreamAdapter and AudioStreamConsumer from
   `contracts/acquisition.py` and verifies your adapter class satisfies both
   protocols. Run it.
3. Write a test that feeds 10 AudioChunks through your adapter and verifies the
   stream_id is consistent, sequence is monotonic, and no chunk has a transport value
   other than "exotel" or "webrtc". Run it.
4. Verify no transport import leaked downstream:
   `grep -r "from acquisitions" backend/ ml/ --include="*.py"` should return nothing.

## If you are blocked

1. Try: search the Exotel documentation site directly. The answer is in their API
   reference or developer guides.
2. Try: if Exotel docs are unclear, test with a minimal integration (connect, check
   what callbacks fire).
3. If still blocked, append to `QUESTIONS.md` using the format in `roles/ROLES.md`.
4. While waiting, switch to: WebRTC adapter work (the fallback path, independent of
   the Exotel answer).

## Never

- Do not edit files outside your folders.
- Do not claim "real time" if Exotel only provides recordings. Use "chunked
  near-real-time" in that case.
- Do not let a backend or ML file import from `acquisitions/`. The invariant test
  catches it, but verify yourself.
- Do not stream audio through your adapter to any external service.
- Do not add the telephony provider SDK as a dependency without asking.
